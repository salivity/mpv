Adjust Buffering Threshold in mpv Media Player

This article explains how to configure the buffering thresholds in the mpv media player to control when a network stream pauses to rebuffer and when it resumes playback. By default, mpv automatically manages its demuxer cache, but you can override the wait times and buffer targets to optimize playback for high-latency, unstable connections or to achieve near-instant stream start times.

Key Buffering Configuration Options

mpv controls the transition between buffering (paused) and playing states using cache-pause settings:

  • cache-pause-wait=<seconds>: Defines how many seconds of media mpv must buffer before it transitions from the buffering state back to the playing state after an underrun. The default is typically 1 second. Increasing this value prevents constant start-stop playback on slow networks, while decreasing it reduces wait times.
  • cache-pause=yes|no: Determines whether playback automatically pauses when the cache runs dry. Leaving this set to yes (the default) ensures audio and video do not desync or drop frames when the network stalls.
  • cache-pause-initial=yes|no: When set to yes, mpv applies the cache-pause-wait threshold at the very beginning of stream playback rather than starting as soon as the first packets arrive.
  • demuxer-readahead-secs=<seconds>: Sets the maximum amount of future media data the player will continuously prefetch into memory. While cache-pause-wait dictates when playback resumes, demuxer-readahead-secs defines the ceiling for how much buffer is maintained during normal playback.

Applying Settings via the Configuration File

To set permanent buffering thresholds, add the parameters to your mpv.conf file:

Linux / macOS: ~/.config/mpv/mpv.conf
Windows: %APPDATA%\mpv\mpv.conf (or portable_config/mpv.conf inside the mpv directory)

Example configuration for an unstable or high-latency connection:

# Enable automatic pause when cache empties
cache-pause=yes

# Require 10 seconds of cached audio/video before resuming playback
cache-pause-wait=10

# Pre-buffer 10 seconds before playing a new stream
cache-pause-initial=yes

# Allow the stream to buffer up to 60 seconds ahead during playback
demuxer-readahead-secs=60

# Increase maximum cache memory allocation to 256 MiB
demuxer-max-bytes=256MiB

Example configuration for low-latency, immediate playback:

# Start immediately with minimal buffer requirement
cache-pause=yes
cache-pause-wait=0.5
cache-pause-initial=no
demuxer-readahead-secs=5

Applying Settings via the Command Line

You can also pass these thresholds directly when launching a stream:

mpv --cache-pause=yes --cache-pause-wait=5 --demuxer-readahead-secs=30 "https://example.com/stream.m3u8"

Monitoring Buffer States During Playback

While a stream is running, press Shift + i to display the on-screen stats. Page 2 of the stats overlay displays real-time details about the cache, including the current buffer fill time in seconds, memory usage, and whether the player is currently in an underrun/buffering state.
