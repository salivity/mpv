Pass HTTP Headers and Cookies to MPV

Streaming media from restricted or paywalled sources often requires sending specific authentication tokens, session cookies, or custom headers. This guide explains how to pass custom HTTP headers, user-agent strings, and authentication cookie files to the mpv media player using both command-line arguments and the mpv.conf configuration file to access protected video streams directly.

Passing HTTP Headers via Command Line

mpv allows you to inject arbitrary HTTP request headers using the --http-header-fields option. This is useful for passing API tokens, referrers, or basic authorization headers.

To pass a single header:

mpv --http-header-fields="Authorization: Bearer YOUR_AUTH_TOKEN" "https://example.com/stream.m3u8"

To pass multiple headers, provide them as a comma-separated list or pass the argument multiple times depending on your shell environment:

mpv --http-header-fields="Authorization: Bearer YOUR_AUTH_TOKEN","Referer: https://example.com/" "https://example.com/stream.m3u8"

Passing Authentication Cookies

There are two primary methods to pass cookies to mpv: using a cookie file or specifying the Cookie header directly.

Method 1: Using a Cookie File

The most reliable approach for complex session data is providing an exported cookie file in Netscape/Mozilla format (easily exported using browser extensions). Use the --cookies-file option:

mpv --cookies-file=/path/to/cookies.txt "https://example.com/stream.m3u8"

If mpv is compiled with yt-dlp support and relies on it to resolve the stream URL, pass the cookie file directly to the extractor backend using --ytdl-raw-options:

mpv --ytdl-raw-options=cookies=/path/to/cookies.txt "https://example.com/video-page"

You can also instruct yt-dlp to extract cookies directly from your installed browser:

mpv --ytdl-raw-options=cookies-from-browser=firefox "https://example.com/video-page"

Method 2: Supplying the Cookie Header Manually

If you only have a simple session cookie string, inject it through the --http-header-fields flag:

mpv --http-header-fields="Cookie: session_id=xyz123abc456" "https://example.com/stream.m3u8"

Spoofing the User-Agent

Servers frequently reject requests that do not come from recognized browsers. You can override the default mpv user-agent string using the --user-agent flag:

mpv --user-agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36" "https://example.com/stream.m3u8"

Persistent Configuration in mpv.conf

To avoid specifying these flags every time, add them to your mpv.conf file (located at ~/.config/mpv/mpv.conf on Linux/macOS or %APPDATA%/mpv/mpv.conf on Windows):

user-agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64)"
cookies-file="~/.config/mpv/cookies.txt"
http-header-fields='Referer: https://example.com/'
