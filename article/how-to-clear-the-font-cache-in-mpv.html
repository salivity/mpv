How to Clear the Font Cache in mpv

When external subtitles in mpv display corrupt characters, missing glyphs, or "tofu" boxes, the issue is frequently caused by an outdated or corrupted font cache generated by the player's underlying subtitle renderer, libass, or the system's fontconfig library. Clearing this cache forces mpv to re-index all installed system fonts on its next startup, restoring proper text rendering without affecting your personal playback settings.

Clearing the Font Cache on Windows

On Windows installations, mpv relies on cached font data stored in your local application directory. Follow these steps to remove it:

  1. Close any running instances of mpv.
  2. Press Win + R to open the Run dialog box.
  3. Type %LOCALAPPDATA% and press Enter.
  4. Look for the fontconfig folder or the mpv folder. Open either and navigate into the cache directory (commonly %LOCALAPPDATA%\fontconfig\cache or %LOCALAPPDATA%\mpv\fonts).
  5. If using a portable installation, open your mpv installation folder and check inside the portable_config folder for a fonts or cache subfolder.
  6. Select and permanently delete all files ending with .cache-* inside these folders.

Clearing the Font Cache on Linux

Linux distributions rely on system-wide and user-level fontconfig directories. You can clear the cache directly via the terminal:

  1. Close mpv.
  2. Open a terminal and run the following command to clear user-level font cache files: 
    rm -rf ~/.cache/fontconfig/*
  3. Rebuild the system font cache completely by executing: 
    fc-cache -r

Clearing the Font Cache on macOS

macOS users running mpv via Homebrew or standalone bundles can purge the cache by removing the local user cache directory:

  1. Quit mpv completely.
  2. Open Terminal from Applications > Utilities.
  3. Remove the cached font files by executing: 
    rm -rf ~/Library/Caches/fontconfig/*
rm -rf ~/.cache/fontconfig/*

Verifying and Rebuilding the Cache

Once you have deleted the cache directories, launch mpv and load a video with the problematic external subtitle file.

The first launch may take several seconds longer than usual while mpv rebuilds its font index. Once indexing finishes, the subtitles will render with refreshed font maps.

Additional Troubleshooting: Subtitle Encoding

If corrupt characters persist after regenerating the font cache, the issue may stem from character encoding mismatches rather than font rendering. Force mpv to read subtitles in UTF-8 or auto-detect the codepage by adding the following line to your mpv.conf file:

sub-codepage=auto

Alternatively, specify a universal fallback font containing broad Unicode coverage in your mpv.conf:

sub-font="Arial"
