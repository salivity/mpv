Force mpv to Use a Specific IP Address or Interface

This guide explains how to force mpv to route its network traffic through a specific network interface or IP address. Because mpv relies on FFmpeg (libavformat) for native streaming and external tools like yt-dlp for media extraction, binding to a specific network endpoint requires configuring both the underlying FFmpeg demuxer protocols and yt-dlp hook arguments.

Binding Direct Media Streams via FFmpeg

When playing direct media links (such as HTTP, HTTPS, HLS, or RTSP streams), mpv relies on FFmpeg’s network protocols. FFmpeg allows you to bind outgoing socket connections to a specific local IP address using the local_addr parameter.

To bind mpv to a specific IP from the command line, pass the option to the stream layer and the demuxer:

mpv --stream-lavf-o=local_addr=192.168.1.50 --demuxer-lavf-o=local_addr=192.168.1.50 "https://example.com/stream.m3u8"

Replace 192.168.1.50 with the local IP assigned to your desired network adapter.

Binding Video Extraction via yt-dlp

If you are streaming from platforms that rely on yt-dlp (such as YouTube, Twitch, or Vimeo), mpv invokes yt-dlp to extract media manifests. You must instruct yt-dlp to bind to the same IP address using the source-address parameter passed through --ytdl-raw-options.

Run the following command:

mpv --ytdl-raw-options=source-address=192.168.1.50 --stream-lavf-o=local_addr=192.168.1.50 --demuxer-lavf-o=local_addr=192.168.1.50 "https://www.youtube.com/watch?v=example"

Making the Configuration Permanent

To ensure all outgoing stream connections automatically use the specified address without typing command-line flags every time, add these parameters to your mpv.conf file:

# Bind FFmpeg network requests to a specific IP
stream-lavf-o=local_addr=192.168.1.50
demuxer-lavf-o=local_addr=192.168.1.50

# Bind yt-dlp network requests to the same IP
ytdl-raw-options=source-address=192.168.1.50

The configuration file is typically located at:

  • Linux/macOS: ~/.config/mpv/mpv.conf
  • Windows: %APPDATA%\mpv\mpv.conf or portable_config/mpv.conf in the mpv directory.

Binding by Network Interface Name (Linux)

FFmpeg's local_addr parameter expects an IP address, not an interface name (e.g., eth0 or wlan0). If you only know the interface name or your IP changes frequently via DHCP:

  1. Look up the assigned IP address using: 
    ip -4 addr show eth0 | grep -oP '(?<=inet\s)\d+(\.\d+){3}'
  2. On Linux, you can alternatively force the entire mpv process and all child processes through a specific interface name using standard network routing tools such as SO_BINDTODEVICE via network namespaces: 
    sudo ip netns exec <namespace_name> sudo -u $USER mpv "<URL>"
