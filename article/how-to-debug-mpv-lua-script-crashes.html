How to Debug mpv Lua Script Crashes

When a Lua script crashes or fails to load in mpv, it typically indicates syntax errors, missing dependencies, or incompatible mpv API calls. This guide walks through practical methods to locate and diagnose these failures, including running mpv from the command line, enabling detailed logging flags, isolating problematic scripts, and capturing runtime Lua errors.

1. Run mpv from the Terminal

By default, GUI-launched mpv instances suppress console logs. Launching mpv directly from your terminal or command prompt displays immediate standard output, including Lua syntax errors and stack traces.

  • Linux / macOS: 
    mpv /path/to/video.mp4
  • Windows (PowerShell / Command Prompt): Use mpv.com instead of mpv.exe to ensure output is written directly to the console: 
    mpv.com "C:\path\to\video.mp4"

Look for lines prefixed with [lua] or [scripts]. A syntax failure will usually provide a file name and line number pointing to the exact problem.

2. Increase Logging Verbosity

If the default terminal output does not reveal the issue, increase mpv's verbosity specifically for Lua operations or export the session to a log file.

  • Target Lua logs specifically: 
    mpv --msg-level=lua=trace /path/to/video.mp4
  • Generate a comprehensive log file: 
    mpv --log-file=mpv_debug.log /path/to/video.mp4

Open mpv_debug.log in a text editor and search for terms like error, failed, or the name of your specific script.

3. Isolate the Script

Other user configurations or conflicting scripts can cause unexpected behavior. Run mpv with user settings disabled while loading only the script in question:

mpv --no-config --script="/path/to/problem_script.lua" /path/to/video.mp4

If the script works under this command, the problem is caused by a conflict with another script or a setting inside your mpv.conf file.

4. Check Common Failure Points

  • API Changes: mpv periodically deprecates older API functions. Verify if the script relies on outdated functions (e.g., using legacy property names or removed utility functions).
  • Missing External Tools: Many mpv scripts wrap external command-line utilities (like yt-dlp, ffmpeg, or curl). If an external binary is not in your system's PATH, the script may exit silently or throw a nil value error.
  • Character Encoding and BOM: Ensure the .lua file is saved with standard UTF-8 encoding without a Byte Order Mark (BOM), as BOM markers can cause parsing errors on initial load.

5. Add In-Script Error Handling

If the script loads but crashes during playback, wrap suspect code blocks using Lua's protected call (pcall) or insert log statements to track execution flow.

Replace direct function calls that might fail with pcall:

local success, result = pcall(function()
    -- Problematic code here
end)

if not success then
    mp.msg.error("Script error caught: " .. tostring(result))
end

You can also use mpv's built-in messaging module to trace execution without breaking the player:

local msg = require 'mp.msg'
msg.info("Checkpoint reached successfully")
