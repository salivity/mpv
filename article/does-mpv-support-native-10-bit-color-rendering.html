Does mpv Support Native 10-Bit Color Rendering?

The open-source media player mpv fully supports rendering 10-bit color depth natively across compatible operating systems, hardware, and display pipelines. By utilizing modern video output backends such as Direct3D 11, Vulkan, and OpenGL, mpv avoids truncating high-bit-depth video down to 8-bit, preserving smooth gradients and preventing banding artifacts. This article details how mpv handles high-bit-depth playback, the hardware and software prerequisites for true 10-bit rendering, and the specific configuration settings required on Windows, Linux, and macOS.

Internal Processing and Native Output

mpv processes all video through a high-precision internal pipeline. When decoding 10-bit sources (such as HEVC Main 10 or VP9 Profile 2), mpv does not automatically truncate the signal. Instead, its video renderers—vo=gpu and the newer vo=gpu-next—convert the decoded frames into high-precision texture formats (typically 16-bit integer or 32-bit floating-point) for color space conversion, scaling, and shader processing.

Native 10-bit presentation occurs when the final rendering target matches the bit depth of the display interface. If the display, graphics driver, and operating system all support a 10-bit (or 30-bit RGB) framebuffer, mpv can directly present frames in 10-bit formats without introducing intermediate 8-bit dithering.

Operating System and Driver Support

Achieving native 10-bit output depends heavily on the host operating system and graphic backends:

  • Windows: Windows supports 10-bit output natively through the Direct3D 11 backend (--gpu-api=d3d11). When connected to a 10-bit or HDR-enabled display, mpv automatically requests a 10-bit swapchain (typically rgb10_a2). To guarantee native 10-bit output, users can explicitly set --d3d11-output-format=rgb10_a2.
  • Linux: Under X11, native 10-bit rendering requires the X server to be configured with a 30-bit color depth (DefaultDepth 30 in xorg.conf). Under modern Wayland environments, native 10-bit and HDR passthrough depend on compositor support, with Vulkan (--gpu-api=vulkan) serving as the most reliable API for high-bit-depth surface negotiation.
  • macOS: Modern macOS systems support 10-bit Wide Color (P3) buffers natively. mpv can output directly to 10-bit surfaces on supported Apple displays using its Cocoa and Metal-adjacent rendering pipelines.

Recommended mpv Configuration for 10-Bit

To ensure mpv utilizes 10-bit rendering whenever the hardware allows, include the following parameters in your mpv.conf file:

# Use modern GPU rendering
vo=gpu-next

# Direct3D 11 on Windows, Vulkan on Linux/cross-platform
gpu-api=auto

# Enforce 10-bit output format for Direct3D 11 (Windows)
d3d11-output-format=rgb10_a2

# Allow mpv to adjust output format dynamically based on display capabilities
target-colorspace-hint=yes

# Automatically handle dithering when outputting to displays below source bit-depth
dither-depth=auto

Setting dither-depth=auto ensures that if a display or graphics driver only negotiates an 8-bit signal, mpv will apply high-quality spatial and temporal dithering to prevent color banding, maintaining visual quality as close to true 10-bit as possible.

How to Verify 10-Bit Output

You can verify that mpv is outputting 10-bit color during playback by pressing Shift + I to open the internal statistics overlay, then pressing 2 to view frame and display information. Under the Display or Output sections, check the target pixel format. Formats labeled as rgb10_a2, bgr10_a2, or any 10-bit/16-bit surface indicate that mpv is delivering native 10-bit rendering directly to your display pipeline.
