mpv HDR10+ Dynamic Metadata with gpu-next

The mpv media player can read and process HDR10+ dynamic metadata when using the gpu-next video output, but its handling depends on whether the goal is internal tone mapping or hardware passthrough to an external display. By leveraging the libplacebo rendering engine, gpu-next utilizes dynamic metadata frame-by-frame to enhance tone mapping, though operating system and graphics driver constraints prevent native HDR10+ passthrough to compatible televisions.

How gpu-next Processes HDR10+

The gpu-next video output driver is built on libplacebo, which works in tandem with FFmpeg to extract HDR10+ metadata. When decoding a video stream containing ITU-T T.35 dynamic metadata (SMPTE ST 2094-40), FFmpeg exposes this information as side data.

libplacebo then reads these frame-by-frame luminance targets and uses them to guide its internal tone-mapping algorithms. Rather than relying on a single, static maximum luminance value for the entire film, mpv dynamically shifts its tone-mapping curves according to the specific needs of bright and dark scenes. This results in significantly improved contrast, reduced highlight clipping, and better shadow detail.

The Passthrough Limitation

While mpv can process HDR10+ metadata internally, it cannot pass native dynamic HDR10+ metadata directly to an external HDR10+ display.

Standard operating system display stacks (Windows Direct3D, Linux Wayland/X11) and modern graphics APIs (Vulkan, OpenGL) currently lack a unified, standardized interface for sending dynamic HDR10+ metadata packets via HDMI or DisplayPort. Consequently, when mpv outputs to an HDR-capable display, the GPU sends a standard static HDR10 signal.

Ideal Use Cases

Because native passthrough is restricted by the platform graphics pipeline, gpu-next handles HDR10+ most effectively in the following scenarios:

  • HDR to SDR Tone Mapping: When playing HDR10+ content on standard dynamic range displays, gpu-next uses the metadata to map colors and luminance accurately into the SDR color space.
  • Target-Nits Tone Mapping for HDR Displays: By configuring mpv with the specific peak brightness of your monitor or TV (via --target-peak), mpv dynamically pre-adjusts the signal to match the display's exact capabilities, performing the dynamic tone mapping in software before the static signal reaches the screen.

In summary, mpv correctly handles HDR10+ metadata under gpu-next for playback and tone mapping via libplacebo, but functions as an internal processor rather than a passthrough conduit for external hardware processing.
