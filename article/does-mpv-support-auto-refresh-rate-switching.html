Does MPV Support Auto Refresh Rate Switching?

mpv does not natively include an automatic display refresh rate switcher out of the box, but it can achieve this functionality through custom Lua scripts and external utilities. While the core philosophy of mpv relies on handling frame rate discrepancies via advanced internal resampling and interpolation, users needing exact hardware display mode changes can configure third-party scripts to switch refresh rates automatically upon media playback.

Why mpv Lacks a Built-In Native Switcher

Unlike media players such as Kodi, mpv is designed to be lightweight and platform-agnostic, deliberately delegating display management to the host operating system and window manager. The development team prioritizes software-level synchronization over changing hardware display modes, which can cause screen flickering, long handshake delays, or multi-monitor arrangement issues.

Achieving Auto Refresh Rate Matching via Scripts

To make mpv physically change your display's refresh rate to match the frame rate of the video (such as switching from 60 Hz to 24 Hz or 23.976 Hz), you must use a Lua script paired with a platform-specific command-line display utility.

  • Windows: Users commonly install community scripts such as mpv-autospeed or custom Lua scripts that invoke command-line tools like ChangeScreenResolution.exe, NirCmd, or QRes. The script reads the container-fps property of the playing file, rounds it to the nearest standard frequency, and executes the external tool to adjust the monitor's display settings.
  • Linux (X11): A Lua script can monitor the playback framerate and call xrandr directly via mpv's mp.command_native to set the appropriate mode.
  • Linux (Wayland): Display mode switching depends heavily on compositor support and is generally managed via compositor protocols or external Wayland tools rather than direct application requests.
  • macOS: Scripts can interface with utilities like displayplacer to adjust the display frequency when a video loads and revert it when playback stops.

The Native Alternative: display-resample and Interpolation

For most modern displays—especially those with 120 Hz, 144 Hz, or variable refresh rate (VRR / G-Sync / FreeSync) panels—manually changing the refresh rate is unnecessary. mpv offers built-in features that eliminate judder without altering screen modes:

  1. video-sync=display-resample: Adjusts audio and video speed slightly to synchronize frame drops and display vsync pulses precisely.
  2. interpolation=yes: Blends or repeats frames smoothly to fit the display's native frequency without the traditional 3:2 pulldown judder.
  3. tscale=oversample (or other interpolation filters): Ensures clean frame pacing on high-refresh-rate monitors.

If your primary goal is smooth playback free of micro-stutter, enabling video-sync=display-resample and interpolation in mpv.conf is the recommended, native solution. If your display requires an exact hardware match (such as older 60 Hz TVs requiring a true 24p mode for film processing), configuring a Lua script is the necessary approach.
