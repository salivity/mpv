Embed mpv Player into Another App Using X11 Window ID

Yes, you can embed the mpv player window directly into another application using an X11 Window ID (WID). mpv natively provides the --wid command-line flag and a corresponding property in its client library (libmpv), allowing developers to redirect video output into a specific container widget provided by another process or GUI toolkit such as Qt, GTK, Tkinter, or raw Xlib.

How to Embed mpv Using --wid

When running the standalone mpv binary as a subprocess, you pass the target window's numeric X11 ID to the --wid parameter:

mpv --wid=<WINDOW_ID> /path/to/video.mp4

In this setup, mpv treats the specified window as its parent window, rendering its video output and default controls within the boundaries of that container rather than creating a new top-level desktop window.

Getting the X11 Window ID in Different Frameworks

To supply the correct identifier to mpv, retrieve the native X11 handle from your GUI container:

  • Qt (C++ / PyQt / PySide): Obtain the ID from a QWidget using the winId() method (e.g., int(widget.winId())).
  • GTK (C / PyGObject): Retrieve the XID from the underlying GDK window using gdk_x11_window_get_xid(gtk_widget_get_window(widget)) after the widget is realized.
  • Python (Tkinter): Access the window handle via the widget’s winfo_id() method (e.g., frame.winfo_id()).
  • Command Line Testing: Find an existing window's ID interactively using utilities like xdotool or xwininfo -root -tree.

Embedding via libmpv (Recommended for Complex Apps)

If you are developing an application with direct library integration rather than launching an external process, you can set the wid property through libmpv:

int64_t wid = your_x11_window_id;
mpv_set_option(mpv_handle, "wid", MPV_FORMAT_INT64, &wid);

This must be configured before initializing the player context (mpv_initialize) or before the video display output is created.

Technical Considerations

  • Input Handling: By default, embedding mpv directs keyboard and mouse events to the video surface. If you want the parent application to manage inputs instead, pass --input-default-bindings=no and --input-vo-keyboard=no.
  • Resizing: The parent window is responsible for managing geometry. When the parent widget resizes, mpv automatically adjusts the video scale to fill the new container dimensions.
  • Wayland Compatibility: The --wid method is specific to X11. Under native Wayland sessions, this mechanism relies on XWayland. For pure Wayland applications, use libmpv's render API (mpv_render_context) with OpenGL or Vulkan rather than window ID reparenting.
