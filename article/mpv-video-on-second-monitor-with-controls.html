MPV Video on Second Monitor with Controls

The mpv media player does not natively support a built-in multi-window mode to separate its video rendering onto a secondary monitor while maintaining a dedicated graphic control window on the primary screen. Because mpv uses a minimalist, single-window architecture where the On-Screen Controller (OSC) is directly composited over the video canvas, moving the player to another screen moves the controls along with it. However, users can achieve this separation by using command-line arguments alongside terminal controls, leveraging its IPC (Inter-Process Communication) interface, or running third-party graphical frontends.

Native Configuration Limits

By default, mpv allows you to route fullscreen video playback directly to an external monitor using the following configuration options or command-line flags:

mpv --fs --fs-screen=1 video.mp4

Here, --fs forces fullscreen, and --fs-screen=1 designates the display index (0 is typically the primary display, while 1 is the secondary). While this places the video on the secondary display, the interactive controls remain layered over the video itself as the On-Screen Controller. Interacting with the video using mouse clicks or hovering must occur on that secondary screen.

Method 1: Terminal Control via Primary Display

If your goal is to manage playback without obscuring the secondary display, you can run mpv directly from a terminal window placed on your primary monitor:

mpv --fs --fs-screen=1 --no-osc --input-terminal=yes video.mp4
  • --no-osc completely disables the graphical interface overlaid on the video.
  • --input-terminal=yes keeps terminal interaction active, allowing you to use standard mpv keyboard shortcuts (such as spacebar for pause, arrow keys for seeking, and 9/0 for volume) inside the terminal on your primary display.

Method 2: IPC Socket and Web Controllers

For a graphical control experience on the primary display, mpv can expose an IPC socket. This allows external tools or browser-based interfaces to drive playback on the secondary display:

  1. Launch mpv with an IPC server:
    • Linux/macOS: mpv --input-ipc-server=/tmp/mpvsocket --fs --fs-screen=1 video.mp4
    • Windows: mpv --input-ipc-server=\\.\pipe\mpvsocket --fs --fs-screen=1 video.mp4
  2. Run an IPC-compatible control client, such as a Python control script or an open-source web remote (like mpv-web-interface).
  3. Open the controller or web interface on the primary screen to pause, scrub, and change playlists while the video plays clean and uninterrupted on the secondary screen.

Method 3: Using a Third-Party Frontend

If you require standard GUI buttons (play, pause, timeline slider) in an independent window on your primary display, consider using an mpv-based frontend rather than the standalone mpv binary:

  • SMPlayer: Uses mpv as its backend engine and natively supports floating/detachable control bars that can remain on a separate display.
  • IINA (macOS): Built on mpv, supporting dedicated mini-players and detached inspector panels that can be separated across screens.
