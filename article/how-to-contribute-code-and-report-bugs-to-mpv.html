How to Contribute Code and Report Bugs to mpv

mpv is an open-source media player developed collaboratively on GitHub, relying on community input to fix issues and expand functionality. This guide provides a straightforward overview of the project's contribution workflows, detailing how to prepare and submit actionable bug reports, propose new feature requests, and submit code contributions through pull requests.

Reporting Bugs

Bug reports for mpv are handled through the project's GitHub issue tracker. Follow these steps to ensure your report is actionable:

  1. Verify the Bug: Test the issue against the latest git master build or the most recent stable release. Bugs that have already been fixed in the development branch will be closed.
  2. Search Existing Issues: Check both open and closed issues to ensure the problem has not already been reported or resolved.
  3. Use the Bug Report Template: When opening a new issue, choose the "Bug report" template. Do not delete the pre-filled checklist or headers.
  4. Provide Required Information:
    • mpv Version: Include the full output of mpv --version.
    • System Details: Specify your operating system, desktop environment, GPU, and graphics driver version.
    • Log File: Generate and attach a complete log file by running mpv --log-file=output.txt [options] [file]. Do not truncate the log.
    • Reproduction Steps: Provide clear, minimal steps to reproduce the issue. If the bug is specific to a media file, provide a short sample or a link to one.

Submitting Feature Requests

Feature requests are also managed via GitHub issues. To request a new capability or change:

  1. Check Prior Discussions: Search the issue tracker to see if the feature was previously requested, implemented under a different name, or explicitly rejected by maintainers.
  2. Use the Feature Request Template: Fill out the issue template detailing the desired functionality.
  3. Explain the Use Case: Clearly describe what problem the feature solves. Explain why the behavior cannot be achieved using mpv's existing configuration options, input commands, or Lua/JavaScript scripting interfaces.
  4. Keep Scope in Mind: mpv prioritizes minimalism, high-quality video output, and scriptability. Features requiring large external dependencies or complex graphical interfaces are generally declined.

Contributing Code

Code contributions are submitted as Pull Requests (PRs) targeting the master branch on GitHub.

Preparation and Guidelines

  • Development Setup: mpv uses the Meson build system. Ensure you can compile the player locally and run tests before making changes.
  • Code Style: Adhere strictly to the existing codebase conventions (primarily C99). Keep code clean, readable, and consistent with the surrounding files.
  • Commit Structure:
    • Keep commits atomic; each commit should represent one logical change.
    • Write clear commit messages following the project's prefix format (e.g., ao_pulse: fix buffer underrun handling or player: add new property).
    • Provide an explanation in the commit body describing why the change is necessary, not just what was changed.

Submitting the Pull Request

  1. Fork the mpv repository and push your changes to a branch on your fork.
  2. Open a Pull Request against the master branch.
  3. Ensure automated CI checks pass. If tests or builds fail, review the logs and push corrections to your branch.
  4. Address review feedback constructively. Maintainers may ask for code refactoring, stylistic changes, or clarification before merging.
