Auto-Switch mpv Audio Profile on Headphone Plug-In

You can configure mpv to apply a specific audio profile automatically when headphones are plugged in by combining mpv's conditional profile engine with device name detection. While mpv does not directly monitor hardware ports, your operating system updates the active audio device upon headphone insertion. By setting up a conditional profile in your configuration file—or using a lightweight Lua script—mpv can detect this audio output change and immediately trigger custom audio filters, volume levels, or equalizer presets.

Step 1: Identify Your Headphone Device Name

Before writing a rule, determine what mpv names your headphone device. Run the following command in your terminal or command prompt:

mpv --audio-device=help

Plug in your headphones and run the command to see the list of active output devices. Note the unique string identifying your headphones (for example, wasapi/{...} on Windows or an ALSA/PulseAudio/PipeWire sink name like alsa/default or pulse/...headphone... on Linux).

Step 2: Configure Conditional Profiles in mpv.conf

mpv features built-in conditional profiles using Lua syntax via the profile-cond property. Open your mpv.conf file (located in ~/.config/mpv/ on Linux/macOS or %APPDATA%/mpv/ on Windows) and define a custom profile.

Add your headphone settings along with a condition that matches the audio device name:

# Define the headphone profile
[headphones]
profile-desc="Headphone Optimizations"
# Condition: triggers when the active audio-device string contains 'headphone'
profile-cond=string.find(audio_device or "", "headphone") ~= nil

# Example settings for headphones:
# Apply crossfeed filter (Bauer stereophonic-to-binaural)
af=lavfi=[bs2b=profile=cmoy]
# Set a safe volume limit
volume-max=100
volume=70

If your operating system does not include the word "headphone" in the device string, replace "headphone" with the exact name or substring found in Step 1.

Step 3: Handling Dynamic Hotplugging via Lua

When headphones are plugged in during playback, some operating systems switch the system-wide default sink automatically, while mpv continues using its initialized device unless configured to watch for updates.

If the conditional profile does not toggle automatically during live playback, you can use a small Lua script to force mpv to re-evaluate the active device.

Create a file named auto-headphones.lua in your mpv scripts directory (~/.config/mpv/scripts/ or %APPDATA%/mpv/scripts/):

mp.observe_property("audio-device", "string", function(name, val)
    if val and string.find(string.lower(val), "headphone") then
        mp.commandv("apply-profile", "headphones")
    else
        -- Restore default settings when unplugged
        mp.commandv("apply-profile", "default-audio")
    end
end)

Pair this with a corresponding fallback profile in mpv.conf:

[default-audio]
af=""
volume=100

With this configuration, mpv actively listens to audio device transitions and switches processing profiles the moment headphones are connected or disconnected.
